I wrote down the habits that make AI coding agents actually useful.

It's 15 pages, in plain words. How to give an agent a task it can't misread. How to stop fixing the same bug three times. Why "done" from an agent means nothing until you check. And a list of red flags that tell you to stop.

There's no course and no sign-up. [Read the playbook (PDF)](/ai-coding-playbook.pdf).

What's inside:

- **The one idea:** you are the lead, the agent is fast hands with no memory
- **Keep the rules short,** and match the process to the size of the task
- **Understand before building,** then write the task down
- **Never accept "done"** until you've checked the changes yourself
- **Root cause, not loops,** and look for the same mistake elsewhere
- **Reviews must prove it:** a finding needs a demonstration, not an argument
- **Red flags:** when to stop

If one developer on your team should read it, send it to them.
